Держи рабочий код. Этот подход позволит тебе не тратить ресурсы GPU на «безнадежные» эксперименты. Мы создадим кастомный **Hook** для MMEngine, который будет связным звеном между процессом обучения и Optuna.

### 1. Реализация OptunaPruningHook

Этот хук будет срабатывать после каждой валидации, забирать метрику и спрашивать у Optuna: «Стоит ли нам продолжать?».

```python
import optuna
from mmengine.hooks import Hook
from mmseg.registry import HOOKS

@HOOKS.register_module()
class OptunaPruningHook(Hook):
    def __init__(self, trial, metric='val/mIoU', interval=1):
        self.trial = trial
        self.metric = metric
        self.interval = interval

    def after_val_epoch(self, runner, metrics=None):
        # 1. Получаем значение метрики из последнего прогона валидации
        if metrics is not None and self.metric in metrics:
            current_score = metrics[self.metric]
        else:
            # Если метрики нет в аргументах, берем из message_hub
            current_score = runner.message_hub.get_scalar(self.metric).current()

        # 2. Сообщаем результат в Optuna
        step = runner.epoch if runner.train_loop.by_epoch else runner.iter
        self.trial.report(current_score, step)

        # 3. Проверка на прунинг (отсечение)
        if self.trial.should_prune():
            message = f"Trial {self.trial.number} pruned at step {step}"
            raise optuna.TrialPruned(message)
```

### 2. Функция Objective для запуска поиска

Здесь мы объединяем конфиг, хук и запуск обучения. 

```python
from mmengine.config import Config
from mmengine.runner import Runner
import torch

def objective(trial):
    # Гиперпараметры для подбора
    lr = trial.suggest_float('lr', 1e-4, 1e-2, log=True)
    backbone_norm_grad = trial.suggest_categorical('norm_grad', [True, False])
    
    # Загружаем базовый конфиг
    cfg = Config.fromfile('configs/deeplabv3plus/deeplabv3plus_r50-d8_4xb2-40k_cityscapes-512x1024.py')
    
    # Модифицируем параметры
    cfg.optim_wrapper.optimizer.lr = lr
    cfg.model.backbone.norm_cfg.requires_grad = backbone_norm_grad
    cfg.work_dir = f'./work_dirs/trial_{trial.number}'
    
    # Добавляем наш кастомный хук в конфиг
    # Важно: trial передается напрямую в хук
    optuna_hook = dict(
        type='OptunaPruningHook', 
        trial=trial, 
        metric='aAcc' # Или 'mIoU', зависит от того, что выдает ваш evaluator
    )
    
    if 'custom_hooks' not in cfg:
        cfg.custom_hooks = [optuna_hook]
    else:
        cfg.custom_hooks.append(optuna_hook)

    # Ускоряем: уменьшаем количество итераций для теста
    cfg.train_cfg.max_iters = 2000 
    cfg.default_hooks.checkpoint.interval = 1000
    cfg.default_hooks.logger.interval = 50

    try:
        runner = Runner.from_cfg(cfg)
        runner.train()
        
        # Финальный результат для Optuna
        metrics = runner.test()
        return metrics['aAcc']
        
    except optuna.TrialPruned as e:
        # Если сработал прунинг, пробрасываем исключение выше для Optuna
        raise e
    except Exception as e:
        # Обработка ошибок (например, Out of Memory)
        print(f"Trial failed due to: {e}")
        return 0.0
```

### 3. Запуск процесса

```python
if __name__ == "__main__":
    # Используем MedianPruner — он отсекает всё, что ниже медианы по точности
    study = optuna.create_study(
        direction='maximize',
        pruner=optuna.pruners.MedianPruner(n_warmup_steps=500)
    )
    
    study.optimize(objective, n_trials=50)

    print(f"Лучший результат: {study.best_value}")
    print(f"Лучшие параметры: {study.best_params}")
```

### Почему это сработает для тебя:
* **Экономия времени:** Как только модель начинает показывать плохие результаты (на фоне других попыток), обучение прерывается.
* **Чистота кода:** Ты не меняешь исходники библиотеки, а просто добавляешь `custom_hook`.
* **Масштабируемость:** Ты можешь добавить в `trial.suggest_...` любые параметры — от типа лосс-функции до `dilations` в бэкбоне.

> [!NOTE]
> Убедись, что в твоем конфиге `val_evaluator` действительно возвращает ту метрику, которую ты указал в `metric='...'`. По умолчанию в MMSeg это обычно `mIoU`, `mAcc` или `aAcc`.
